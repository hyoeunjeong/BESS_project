# 딥러닝 순부하 예측을 활용한 BESS 운영 성능 분석

> 태양광 연계 **BESS(Battery Energy Storage System, 배터리 에너지 저장장치)**를
> **규칙 기반 · LSTM · GRU** 세 가지 방식으로 제어·시뮬레이션하고,
> **경제성 · 에너지 효율 · 운영 안정성 · 예측 정확도**를 다각도로 비교하는 학사학위논문 코드베이스입니다.

한국전력거래소(SMP)·공공데이터포털(부하)·기상청(일사량) **2025년 실측 1년치(8,760시간)** 데이터를 사용하며,
세 방식이 **동일한 데이터·동일한 제어 정책**을 쓰고 **예측기만 다르도록** 설계해 공정하게 비교합니다.

## 1. 연구 배경과 질문

건물 옥상 태양광과 연계된 소규모 BESS는 **언제 충전하고 언제 방전하는가**에 따라
전기요금·배터리 수명·계통 안정성이 크게 달라집니다. 이 프로젝트는 다음을 검증합니다.

- **Q1.** 딥러닝 순부하 예측(LSTM·GRU)이 규칙 기반 제어보다 나은가?
- **Q2.** 예측 정확도(MAE)가 실제 운영 성과(요금·안정성)로 직결되는가?
- **Q3.** 요금 체계(연중 단일 vs 계절별)에 따라 우열이 어떻게 달라지는가?

핵심 개념은 **순부하(net load) = 부하 − 태양광**입니다. 예측 모델은 다음 1시간의 순부하를 예측하고,
제어기가 그 예측으로 충·방전을 결정합니다.

## 2. 데이터

| 항목 | 출처 | 비고 |
|---|---|---|
| 전력 부하 | 공공데이터포털 ODcloud API | 시간별, 평균 50 kW로 스케일 |
| SMP(계통한계가격) | 전력거래소 API | 육지 기준, 24시각×365일 = 8,760h |
| 태양광 발전 | 기상청 ASOS 일사량(icsr) | `solar = clip(icsr × 용량 × 0.2778, 0, 용량)` |

- **평가 구간**: 2025-01-01 ~ 2025-12-31, 8,760시간 → 시퀀스(길이 24) 소모 후 **8,736시점**

- **예측 타깃**: 다음 1시간 순부하 `max(부하 − 태양광, 0)`

> 데이터·모델·결과는 용량/보안상 `.gitignore`로 제외됩니다. 최초 실행 시 API 수집·학습이 필요합니다.

## 4. 제어 방식

### 4.1 규칙 기반 (Rule-Based)

단순 TOU(시간대별 요금) 차익거래 규칙:
1. 태양광 잉여(순부하<0) → 충전
2. 순부하>0 이고 중간/최대부하 시간 → 방전
3. 경부하 시간 + 대기 → 계통에서 충전

→ SOC를 10~90% 풀스윙하며 공격적으로 차익거래.

### 4.2 예측 기반 (LSTM · GRU)

**예측 모델** — Stacked (LSTM|GRU) 2층 · hidden 128 · dropout 0.2 · Adam(lr 1e-3) · MSE ·
Early Stopping(patience 10) · ReduceLROnPlateau · grad clip 1.0 · **시드 42 고정**.
두 모델은 구조가 동일하고 순환 셀(LSTM↔GRU)만 다릅니다.

**제어기** — 우선순위 기반(P0→P3). LSTM·GRU가 **완전히 동일한 제어 로직**을 쓰고 예측값만 다릅니다.

| 우선순위 | 조건 | 동작 |
|---|---|---|
| P0 | SOC 위험(하한/상한 근접) | 비상 충전/방전 |
| P1 | 실측 태양광 잉여 | 잉여만큼 충전 (커튼일먼트 방지) |
| P2 | 예측 순부하 > 피크 임계값 | 피크 컷 방전 |
| P3 | 그 외 | 시간대별 SOC 목표 추종(경0.80/중0.60/최0.20) |

**제어기 정정 사항** (논문의 방법론적 기여, LSTM·GRU 동일 적용):

- **(가) 역송 방지** — 모든 방전 상한을 실측 순부하 `max(부하−PV,0)`로 제한 → 계통 역송 0
- **(나) SOC 진동 제거** — 경부하 목표 0.90→0.80 (비상 임계 0.85와의 간섭 제거)
- **(다) 조건부 충전 → (#3) 경부하 전용 충전** — 비싼 중간/최대부하 계통 충전 전면 금지
- **(라) 충전 오버슈트 클램프** — SOC가 목표를 넘어 상승하는 진동 억제
- **(마) 데이터 누수 차단** — 피크 임계값을 **학습 구간(앞 70%)** 부하로만 산출
- **태양광 우선 흡수** — P1을 예측이 아닌 **실측 잉여** 기준으로 충전 → 커튼일먼트 최소화

## 5. 전력요금 체계 (TARIFF_MODE)

`config.py`의 `TARIFF_MODE` 한 줄로 두 요금 체계를 전환합니다.

### `'paper'` — 연중 단일 (논문 본문 재현, 기본값)

| 시간대 | 시각 | 단가 |
|---|---|---|
| 최대부하 | 10·11·13·14·15·16시 | 180 원/kWh |
| 중간부하 | 9·12·17~22시 | 110 원/kWh |
| 경부하 | 그 외 | 60 원/kWh |

### `'seasonal'` — 계절별 (실제 산업용(갑)Ⅱ 고압A, 민감도 분석)

| 계절 | 경/중/최 (원/kWh) | 최대부하 시각 |
|---|---|---|
| 여름(6~8월) | 90.8 / 116.6 / 150.1 | 15~21시 |
| 봄·가을 | 90.8 / 95.6 / 114.8 | 15~21시 |
| 겨울(11~2월) | 98.2 / 115.1 / 144.5 | 9~12·16~19시 |

> `paper`는 최대부하가 **낮**(태양광과 겹침), `seasonal`은 **저녁**(태양광 없음)이라 결과가 크게 달라집니다(§10.2).

기본요금은 최대수요전력 기준 `BASE_CHARGE_WON_PER_KW = 7470` 원/kW·월.

## 6. 평가 지표

`evaluator.py`가 산출하는 지표 (논문 표 대응).

**경제적 효율**
- `요금 절감률` / `절감액` — 무제어 대비 전력량요금 절감
- `최대부하 절감률` — 최고 요금대 절감
- `최대수요전력 저감률` — 계통 순시 최대전력 변화(기본요금 영향)
- `기본요금 증감` / `순 절감액` — 요금 절감에서 기본요금 증가를 차감

**에너지 효율**
- `태양광 이용률` · `커튼일먼트` — 태양광 활용/낭비
- `BESS 활용률` · `자립률` · `라운드트립 효율` · `BESS 기인 역송`

**운영 안정성 · 수명**
- `SOC 권장구간(20~80%) 체류율` · `SOC>80%` · `SOC<20% 심방전`
- `배터리 사이클 수` · `일일 전환 빈도` · `과충·과방전 횟수`

**예측 정확도** (LSTM·GRU)
- `MAE` · `RMSE` · `상대오차(정규화 MAE)`

**SOC 안정성·수명·태양광 이용률에서 예측 기반의 우위는 두 요금 체계 모두 유지**됩니다.

## 11. 주요 발견과 결론

- **예측 정확도 ≠ 운영 성과** — LSTM이 MAE는 낮지만(1.576<1.751), 운영은 GRU와 대등하고 경제성은 GRU가 근소 우위.
- **트레이드오프** — 규칙기반은 "지금 아끼고 배터리를 태우는" 방식(심방전 45%, 사이클 298),
  예측 기반은 "조금 덜 아끼되 배터리를 오래 쓰는" 방식(심방전 12%, 사이클 249).
- **장기 총소유비용** — 배터리 교체비(수천만원)를 고려하면 예측 기반(특히 GRU)이 지속가능.
- **요금 의존성** — 경제적 우열은 요금 구조가 가르지만, 배터리 수명·안정성 우위는 요금과 무관하게 예측 기반이 지킴.

## 12. 한계와 후속 과제

- 예측 모델은 단일 시드(42) 결과 — 강건성 확인엔 `seed_sweep.py`로 다중 시드(42/1/7/13/2024) 반복 권장.
- 계절 요금(`seasonal`)은 낮-피크용으로 튜닝된 제어기를 그대로 적용 — 저녁-피크 전용 재조정 시 결과가 달라질 수 있음.
- 배터리 열화 비용(DoD 기반 LCOS)을 정량화하면 장기 경제성 비교를 강화할 수 있음.
- 태양광은 일사량 선형 모델 — 성능비·온도 보정을 반영한 물리 모델로 확장 가능.
