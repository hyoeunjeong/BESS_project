# 딥러닝 기반 순부하 예측을 활용한 BESS 운영 성능 분석

> 태양광 연계 **BESS(Battery Energy Storage System, 배터리 에너지 저장장치)** 를
> **규칙 기반 · LSTM · GRU** 세 가지 방식으로 제어·시뮬레이션하고,
> **경제성 · 에너지 효율 · 운영 안정성 · 예측 정확도** 를 다각도로 비교하는 학사학위논문 코드베이스입니다.

한국전력거래소(SMP)·공공데이터포털(부하)·기상청(일사량)의 **2025년 실측 1년치(8,760시간)** 데이터를 사용하며,
**LSTM·GRU는 동일한 데이터·동일한 제어 로직** 을 쓰고 예측기만 다르며, **규칙 기반은 예측 없이 동작하는 별도의 제어 정책** 으로서 비교 기준(baseline) 역할을 합니다.
결과 수치는 저장소 코드로 재생성됩니다 — 담당 스크립트는 §10 표를 참조하세요.

## 1. 연구 배경과 질문

### 1.1 배경

탄소중립과 분산형 전원 확대로 태양광 발전 비중이 빠르게 늘고 있으나, 태양광은 일사량·기상에 따라
출력 변동성이 크다. 태양광이 집중되는 **주간** 과 수요가 높은 **저녁 피크** 사이의 시간적 불일치는
**순부하(net load = 전력 수요 − 태양광 발전량)** 곡선을 낮에 급감했다가 저녁에 급증하는
**덕 커브(duck curve)** 형태로 만들며, 발전기의 급격한 출력 조정(ramping)과 계통 운영 부담을 유발한다.
태양광 비중이 높은 지역에서는 공급 과잉에 따른 **출력제한(curtailment)** 손실도 발생한다.
또한 국내 산업용 요금 체계는 여름철 주간이 최대부하 구간이라 **태양광 발전 시간대와 고요금 시간대가
부분적으로 중첩** 되어, 저장뿐 아니라 발전 시간대 내 충·방전 판단도 운영 성과를 좌우한다.

### 1.2 필요성 — BESS와 운영 알고리즘

**BESS** 는 잉여 전력을 저장했다가 필요 시점에 방전해 태양광 변동성을 완화한다. 에너지 아비트리지(요금 차익),
부하 이전(load shifting), 피크 저감 등을 수행하는 핵심 수단이지만, **언제 충·방전할지를 결정하는 운영 알고리즘**
에 따라 동일 용량이라도 요금 절감·피크 저감·활용률에서 큰 성과 차이가 난다. 따라서 하드웨어 성능뿐 아니라
**충·방전 시점 결정 전략의 설계** 가 시스템 효율을 좌우한다.

### 1.3 기존 방식의 한계

기존 BESS 운전은 주로 **규칙 기반(rule-based)** 제어에 의존한다. 구현이 단순·안정적이지만, **미래를 예측하지 않고**
현재 시점·사전 정의된 시간대에만 의존해 의사결정하므로 부하·발전량의 급변에 유연하게 대응하지 못한다. 실제 값이
예상과 다르면 상황에 맞지 않는 충·방전을 내려 배터리를 비효율적으로 운용하거나, 정작 필요한 시점에 저장 여유/방전
용량을 확보하지 못한다. 계절·요일·기상에 따른 패턴 다양성도 반영하기 어려워 확장성·적응성에 한계가 있다.

### 1.4 목적과 연구 질문

본 프로젝트는 **딥러닝으로 순부하를 예측** 하고 그 예측으로 BESS 충·방전 전략을 수립하여, 규칙 기반과의 운영 성능을
정량 비교한다. 운영 성능은 요금 절감이라는 단일 관점이 아니라 **(Ⅰ) 경제적 효율, (Ⅱ) 에너지 효율, (Ⅲ) 운영 안정성**
의 세 관점에서 종합 평가하며, 특히 **예측 정확도의 향상이 실제 운영 성과로 이어지는지, 그렇지 않다면 그 원인은
무엇인지** 를 규명하는 데 초점을 둔다. 순부하 예측에 널리 쓰이는 **LSTM·GRU** 두 모델을 규칙 기반과 함께 비교한다.

- **Q1.** 순부하 예측에서 LSTM과 GRU의 예측 성능은 어떤 차이를 보이는가.
- **Q2. [경제적 효율]** 예측 기반 운영은 규칙 기반 대비 전력요금 절감·피크 대응에서 어떤 차이를 보이며, 그 차이는 무엇에서 비롯되는가.
- **Q3. [에너지 효율·운영 안정성]** 예측 기반 운영은 충·방전 효율과 SOC 안정성에서 규칙 기반과 어떤 차이를 보이는가.

> 본 저장소는 이 질문들을 실제 시계열 데이터 기반 시뮬레이션으로 검증하여, 딥러닝 예측이 실제 BESS 운영 성능에
> 미치는 영향을 실증적으로 확인한다.

## 2. 데이터와 전처리 파이프라인

세 가지 실측 공공데이터를 시간 단위로 병합해 1년치(8,760시간) 시계열을 만든다.

| 항목 | 출처 | 처리 방법 |
|---|---|---|
| **전력 부하** | 공공데이터포털 ODcloud API | 시간별 수요를 연평균 **50 kW** 기준으로 스케일 |
| **SMP**(계통한계가격) | 전력거래소(KPX) | **육지 기준**, 24시각 × 365일 = 8,760h |
| **태양광 발전** | 기상청 ASOS 일사량(`icsr`) | `solar_kw = clip(icsr × 50 kW × 0.2778, 0, 50)` |

### 2.1 파이프라인 단계 (`data_loader.py`)

1. **수집** — 각 API에서 1년치를 받아 캐시(`data/api_cache/`)에 저장. 이후 실행은 캐시를 재사용한다.
2. **병합** — `timestamp` 기준 inner join 으로 부하·SMP·태양광을 정렬한다.
3. **진위 검증** — `_validate_series()` 가 각 계열의 고유값 비율과 일간 프로파일 반복성을 점검한다.
   (예: 365일이 동일한 프로파일을 반복하는 "가짜 SMP" 를 자동 탐지한다.) `STRICT_DATA = True`(기본값)이면
   CSV/합성 데이터로의 **폴백을 차단** 하고, 데이터 출처·기간·결측을 콘솔에 명시한다.
4. **피처 엔지니어링** — 아래 12개 입력 피처를 생성하고, 시퀀스 길이 24로 슬라이딩 윈도우를 만든다.

### 2.2 입력 피처 (12개) · 예측 타깃

```
load_kw, solar_kw, net_load_kw, smp, tariff_rate,          # 물리량·요금
hour_sin, hour_cos, dow_sin, dow_cos, month_sin, month_cos, # 시각·요일·월 순환 인코딩
is_weekend                                                  # 주말/공휴일 여부
```

- **순환 인코딩** — 시각(0~23)·요일(0~6)·월(1~12)의 주기성을 `sin/cos` 쌍으로 표현해 "23시→0시" 의 불연속을 없앤다.
- **예측 타깃** `net_load_kw = max(부하 − 태양광, 0)` — 다음 1시간 순부하. 역송(순부하<0)은 저장 대상이 아니므로 **0으로 하한 클리핑** 한다.
- **평가 구간** — 8,760시간에서 시퀀스(길이 24)를 소모하고 남는 **8,736시점** 을 시뮬레이션한다.

> 데이터·학습 모델·API 키는 용량/보안상 `.gitignore` 로 제외됩니다. 최초 실행 시 API 수집·학습이 필요합니다.

## 4. 제어 방식

세 방식 모두 **1시간 단위** 로 충·방전을 결정하고 SOC를 갱신한다. 방전 시 계통으로의 역송을 막기 위해 모든 방전량은
그 시각의 **실측 순부하** 를 넘지 않도록 제한된다.

### 4.1 규칙 기반 (Rule-Based) — `rule_based/bess_controller.py`

미래를 보지 않는 단순 TOU(시간대별 요금) 차익거래 규칙:

1. **태양광 잉여**(순부하 < 0) → 잉여만큼 **충전** (`solar_surplus`)
2. **순부하 > 0** 이고 **중간·최대부하** 시간대 → **방전** (`peak_discharge`)
3. **경부하 + 대기** 상태 → 계통에서 **충전** (`offpeak_grid_charge`)

→ SOC를 10~90% 로 **풀스윙** 하며 공격적으로 차익거래한다. 단순하지만 배터리를 깊게 쓰고(심방전 잦음), 최대수요전력을
낮추지는 못한다.

### 4.2 예측 기반 (LSTM · GRU) — `DL_LSTM` · `DL_GRU`

**예측 모델** — Stacked (LSTM|GRU) **2층 · hidden 128 · dropout 0.2**, Adam(lr 1e-3), 손실 MSE, 배치 32,
최대 100 epoch, **Early Stopping**(patience 10) + `ReduceLROnPlateau`, gradient clipping 1.0, **시드 42 고정**.
두 모델은 구조가 완전히 동일하고 순환 셀(`nn.LSTM` ↔ `nn.GRU`)만 다르다.

**제어기** — 아래 **우선순위 계층** 으로 매 시각 하나의 동작을 결정한다. LSTM·GRU가 **완전히 동일한 제어 로직** 을
쓰고 입력되는 예측값만 다르다.

| 우선순위 | 계층 | 조건 | 동작 |
|---|---|---|---|
| **0 (최우선)** | `demand_charge_cut` | 중간·최대부하에서 **실측** 순부하 > 수요 상한 | 초과분만큼 방전해 요금적용전력 억제 |
| 1 | `P0` 비상 보호 | SOC가 하한/상한 5%p 이내 | 비상 충전/방전(충전은 수요 상한 headroom 이내) |
| 2 | `P1` 태양광 흡수 | **실측** 태양광 잉여 발생 | 잉여만큼 충전 (커튼일먼트 방지) |
| 3 | `P2` 피크 컷 | **예측** 순부하 > 피크 임계값 | 임계 초과분 방전 |
| 4 | `P3` SOC 목표 추종 | 그 외 | 시간대별 SOC 목표(경 0.80 / 중 0.60 / 최 0.20) 추종 |

**수요전력 관리 계층(최우선)** — 학습 구간(앞 70%)의 무제어 요금적용전력을 `P_CAP`(= 71.24 kW)로 잡고,
`DEMAND_SHAVE = 0.90` 을 곱한 **목표 상한 64.11 kW** 를 넘는 실측 순부하가 발생하면 우선적으로 방전한다.
비상 충전조차 이 상한을 밀어올리지 못하도록 `headroom` 제약을 둔다. 이 계층 덕분에 예측 기반은 요금적용전력을
71.24 → 70.48 kW 로 낮춰 **기본요금을 연 67,259원 절감**(규칙기반 0원)한다.

**제어기 정정 사항** (방법론적 기여, LSTM·GRU 동일 적용):

- **(가) 역송 방지** — 모든 방전 상한을 실측 순부하 `max(부하−PV, 0)` 로 제한 → 계통 역송 0
- **(나) SOC 진동 제거** — 경부하 SOC 목표 0.90 → 0.80 (비상 방전 임계 0.85와의 간섭 제거)
- **(다) 경부하 전용 계통 충전** — 비싼 중간·최대부하 시간대의 계통 구매 충전을 전면 금지
- **(라) 충전 오버슈트 클램프** — SOC가 목표를 넘어 상승하는 진동 억제
- **(마) 피크 임계값 누수 차단** — 피크 임계값을 **학습 구간(앞 70%)** 부하로만 산출
- **(바) 충전 전력의 계통 측 상한** — 중간·최대부하 시간대의 모든 충전 경로에 `P_head = P_tgt − 실측 순부하` 상한을 부여하고, 순부하가 목표를 넘으면 억제 방전하는 `demand_charge_cut` 계층을 최상위에 신설. 이 정정으로 요금적용전력이 82.98 → 70.48 kW로 낮아지고 순 절감액의 부호가 반전된다(표 2.11 F 단계).
- **태양광 우선 흡수** — P1을 예측이 아닌 **실측 잉여** 기준으로 충전 → 커튼일먼트 최소화

## 5. 전력요금 체계 (TARIFF_MODE)

`config.py` 의 `TARIFF_MODE` 한 줄로 요금 체계를 전환한다. 시간대·단가 정의만 달라지고 **제어 정책은 동일** 하다.

### `'seasonal'` — 계절별 실요금 (**기본값 · 재현/비교 기준**)

2025년 시행 산업용(갑)Ⅱ 고압A 선택Ⅱ 요금표를 반영한다.

| 계절 | 경 / 중 / 최 (원/kWh) | 최대부하 시각 |
|---|---|---|
| 여름(6~8월) | 90.8 / 116.6 / 150.1 | 11~12시 · 13~18시 |
| 봄·가을 | 90.8 / 95.6 / 114.8 | 11~12시 · 13~18시 |
| 겨울(11~2월) | 98.2 / 115.1 / 144.5 | 9~12시 · 16~19시 |

> 최대부하 시각은 **구간 표기**다(`11~12시` = 11:00–12:00, `config.py` 의 `hour=11`).
> `_BANDS_2025` 정의: 여름·봄가을 `on={11,13,14,15,16,17}`, 겨울 `on={9,10,11,16,17,18}`.

**요일·공휴일 규칙** — 일요일·법정공휴일은 종일 **경부하**, 토요일의 최대부하 시각은 **중간부하** 로 강등한다.
그 결과 1년 중 최대부하는 **1,476시간**, 중간부하 2,696시간, 경부하 4,588시간이 된다.

### 그 밖의 모드 (민감도 분석용)

- **`'2026'`** — 2026년 개편 시간대. **여름·봄가을 최대부하가 15~21시(저녁)로 이동**(`on={15,16,17,18,19,20}`), 겨울은 2025와 동일. 요금 개편 민감도 분석용.
  **단가는 `'seasonal'` 과 동일한 `SEASONAL_TARIFF` 를 재사용하므로, 시간대 이동 효과만 분리 관찰하는 용도다**(§11.3 경고 참조).
- **`'paper'`** — 60 / 110 / 180 원/kWh 의 **가상 시나리오**. 실존하지 않으며 재현/비교 기준이 아니다(참고용).

기본요금은 요금적용전력(중간·최대부하 시간대 순시 최대전력, 계약전력의 30% 를 하한으로 함) 기준
`BASE_CHARGE_WON_PER_KW = 7,470` 원/kW·월로 산정한다.

## 6. 평가 지표

`evaluator.py` 가 세 범주 지표를 산출한다.

**Ⅰ. 경제적 효율**
- `전력요금 절감액 / 절감률` — 무제어 대비 전력량요금(kWh 사용요금) 절감
- `최대부하 절감률` — 최고 요금대 사용요금 절감
- `요금적용전력 / 최대수요전력 저감률` — 중간·최대부하 시간대 순시 최대전력(기본요금의 기준)
- `기본요금 증감` · **`순 절감액`** — 전력량요금 절감에서 기본요금 증감을 차감한 최종 절감

**Ⅱ. 에너지 효율**
- `커튼일먼트` · `태양광 이용률` — 태양광 낭비/활용
- `BESS 활용률` · `에너지 자립률` · `라운드트립 효율` · `BESS 기인 역송`
- `총 처리 에너지` · `배터리 사이클 수` — 배터리 수명 소모의 척도

**Ⅲ. 운영 안정성 · 수명**
- `SOC 권장구간(20~80%) 체류율` · `SOC>80%` · `SOC<20% 심방전` 비율
- `과충·과방전 횟수` · `일일 전환 빈도`

**예측 정확도** (LSTM·GRU) — `MAE` · `RMSE` · `상대오차(평균 순부하로 정규화한 MAE)`.
타깃은 학습과 동일하게 0 하한 클리핑한 순부하이며, **test 구간(뒤 15%)** 값을 대표 지표로 싣는다(§7·§10).

## 7. 방법론적 신뢰성 — 누수 차단·재현성

논문 심사에서 방어 가능하도록, 흔한 데이터 누수 경로를 코드 수준에서 차단하고 모든 수치를 재현 가능하게 만들었다.

- **스케일러 학습 구간 fit** — `MinMaxScaler` 를 **학습 구간(앞 70%, 6,132행)** 으로만 `fit` 한다.
  전체(val/test 포함)로 정규화하던 기존 방식의 미래 정보 누수를 제거했다.
- **예측 지표 구간 분리** — 예측 오차를 train / val / **test** / full 로 나눠 산출하고, 대표값은 **test** 를 쓴다.
  (누수 제거 후 test MAE는 LSTM 1.290 / GRU 1.306 kW. test가 연말 겨울이라 태양광 간헐성이 낮아 full보다 낮다 — 누수가 아니다.)
- **피크 임계값·수요 상한** — FULL_YEAR 여부와 무관하게 항상 **학습 구간(앞 70%)** 에서만 산출한다.
- **데이터 진위 검증·STRICT 모드** — 합성/캐시 폴백을 차단하고 가짜 계열을 탐지한다(§2).
- **재현 검증** — `verify_reproduction.py`(규칙 기반 13지표)와 `compare.py`(3자 동일 구간 비교)로
  논문 표의 모든 수치를 저장소 코드만으로 재생성한다.

`TARIFF_MODE='2026'`(여름·봄가을 최대부하가 15~21시 저녁으로 이동)로 세 방식을 재실행해 `'seasonal'` 과
비교했다(**동일 모델·동일 제어 정책**, 시드 42, `SKIP_TRAINING=True`). `'paper'`(가상 요금)는 재현/비교
기준이 아니므로 제외했다.

> **⚠ `'2026'` 모드의 반영 범위** — 본 민감도 분석은 개편안 중 **시간대 구분(`_BANDS_2026`)만**
> 반영하며, **단가는 2025년 `SEASONAL_TARIFF` 값을 그대로 사용**한다(`config.py` 주석
> "seasonal·2026 공용"). 실제 개편은 단가도 조정하므로(낮 최대부하 시간대 인하·경부하 인상),
> 아래 수치는 **시간대 이동 효과만 분리한 결과**다. 경부하 단가 인상은 BESS 충전 비용을
> 직접 올리므로 단가를 반영하면 절감액이 감소하는 방향으로 작용할 수 있다.
> 또한 봄·가을 주말·공휴일 낮 시간 전력량요금 할인, 계약종별 시행일 차이는 미반영이다.

| 지표 | 모드 | Rule-Based | LSTM | GRU |
|---|---|---:|---:|---:|
| **순 절감액 (원)** | seasonal | 285,497 | 398,281 | **400,442** |
| | 2026 | 281,106 | 335,326 | **339,492** |
| 요금 절감률 (%) | seasonal | 0.75 | 0.87 | 0.87 |
| | 2026 | 0.73 | 0.87 | **0.88** |
| 최대부하 절감률 (%) | seasonal | 9.79 | 16.57 | **16.58** |
| | 2026 | 7.59 | 13.53 | **13.66** |
| 기본요금 증감 (원) | seasonal | 0 | −67,259 | −67,259 |
| | 2026 | 0 | 0 | 0 |

**관찰**

- **순 절감액의 우열 구조(GRU ≳ LSTM ≫ Rule-Based)는 두 요금 체계에서 모두 유지된다.**
- 그러나 **§4 수요전력 관리(`demand_charge_cut`) 이득은 seasonal 전용**이다. 2026에서는 최대부하가 저녁으로
  이동해 연중 최대수요 시각 구성이 달라지며, 세 방식 모두 요금적용전력 71.24 kW·기본요금 증감 0원이 되어
  예측 기반의 기본요금 절감(−67,259원)이 사라진다. 즉 **예측 기반 우위의 원천이 요금 체계에 따라 달라진다**
  (seasonal: 에너지 차익 + 기본요금 절감 / 2026: 에너지 차익 중심).
- 계절 분해(그림 2.6)에서는 겨울철처럼 규칙 기반이 근접·우세할 수 있는 구간도 있어, 우열은 요금 체계·계절에
  따라 정도가 달라진다.

### 11.4 예측 소스 Ablation — 정확도 역전 현상

동일 제어기에서 **예측 소스만 교체**해 재실행했다(`DL_LSTM/_ablation_run.py`,
→ `results/prediction_contribution.csv`). 결과는 예측 정확도와 순 절감액이 **단조 관계가
아님**을 보여준다.

| 예측 소스 | test MAE (kW) | 전력량요금 절감(원) | 요금적용전력(kW) | 기본요금 증감(원) | **순 절감액(원)** |
|---|---:|---:|---:|---:|---:|
| persistence (직전값) | 5.056 | 341,336 | 69.15 | −186,875 | **528,211** |
| no_pred (무예측) | 44.977 | 327,477 | 69.75 | −132,716 | **460,192** |
| perfect (완전예측) | 0.000 | 344,895 | 70.48 | −67,259 | **412,154** |
| GRU | 1.306 | 333,184 | 70.48 | −67,259 | **400,442** |
| LSTM | 1.290 | 331,022 | 70.48 | −67,259 | **398,281** |

**해석 — 왜 부정확한 예측이 더 많이 절감하는가**

순 절감액의 역전은 **전력량요금이 아니라 기본요금 항에서** 발생한다. 전력량요금 절감만 보면
순서가 정상(perfect 344,895 > persistence 341,336 > GRU 333,184 > LSTM 331,022 >
no_pred 327,477)이다. 그러나 기본요금 증감은 persistence −186,875원, no_pred −132,716원으로
LSTM/GRU(−67,259원)의 2~3배다.

원인은 요금적용전력(중간·최대부하 시간대 순시 최대전력)이다. 부정확·보수적인 예측은 충전을
과소 결정해 계통 순부하 첨두를 덜 밀어올리고, 그 결과 요금적용전력이 69.15 / 69.75 kW 로
정확한 예측(70.48 kW)보다 **낮게** 형성된다. 기본요금이 연 7,470원/kW·월 단가로 곱해지므로
1 kW 차이가 전력량요금 절감분을 상쇄할 만큼 크다.

**논문에 대한 함의**

1. 본 시스템의 순 절감액은 **예측 정확도보다 요금적용전력 관리에 훨씬 민감**하다.
   §4 `demand_charge_cut` 계층의 설계가 예측기 선택보다 성과를 좌우한다.
2. 따라서 "딥러닝 예측이 규칙 기반보다 우수하다"(§11.1, §12)는 결론은
   **규칙 기반 대비로는 유효하나, 단순 지속 모델 대비로는 성립하지 않는다.**
   §12 의 결론 서술은 이 범위로 한정해 읽어야 한다.
3. 이는 예측 신호의 기여를 키우는 예측–제어 통합 설계가 필요하다는 §13 후속 과제와 직결된다.

## 12. 주요 발견과 결론

- **예측 기반이 경제성·안정성 전반에서 규칙 기반을 앞선다** — 순절감 GRU 400,442 / LSTM 398,281원
  vs 규칙 285,497원(+40%). SOC 안정성·배터리 수명도 예측 기반 우위.
  단, 이 우위는 **규칙 기반 대비**로 한정된다. 단순 지속(persistence) 예측은 순절감
  528,211원으로 딥러닝을 앞서며, 그 원인은 요금적용전력 형성 차이다(§11.4).
- **LSTM vs GRU** — 5시드 반복 결과 예측 정확도(1.203 ± 0.066 vs 1.283 ± 0.142 kW, p = 0.299)와 순 절감액(403,940 ± 3,835 vs 411,239 ± 21,272원) 모두 통계적으로 유의한 차이가 없다. **두 모델은 동급이며, 시드 간 변동만 GRU가 2.15배 크다.**
- **예측 정확도 ≠ 운영 성과** — 시드 간 변동계수가 예측 지표(LSTM 5.5%, GRU 11.1%)보다
  경제 지표(0.95%, 5.17%)에서 훨씬 작다. 예측 모델의 확률적 변동이 운영 성과로 그대로
  전달되지 않는다. Ablation(`results/prediction_contribution.csv`)에서도 무예측(no_pred)
  대비 완전예측(perfect)까지의 전력량요금 개선 폭 중 LSTM 이 실현한 몫은 **20.4%**
  (= (331,022 − 327,477) / (344,895 − 327,477)) 에 그쳐, 개선분의 대부분이 제어 구조에서
  발생함을 뒷받침한다.
- **수요전력 관리 계층(§4)** — 실측 순부하 기반 상한 관리로 요금적용전력을 71.24 → 70.48 kW 로 낮춰 기본요금을 연 67,259원 절감(규칙기반 0원).
- **트레이드오프** — 규칙기반은 공격적 풀스윙(심방전 38.7%, 사이클 243)으로 총처리에너지는 크지만 배터리를 태우고,
  예측 기반은 보수적 운용(심방전 7.9%, 사이클 186)으로 수명을 아낀다.

## 13. 한계와 후속 과제

- **시드 표본 수(n=5)** — `seed_sweep.py` 로 시드 42/1/7/13/2024 를 반복했으나(§11.1·§12),
  n=5 는 Welch t-검정의 검정력이 낮아 "차이 없음"을 적극적으로 입증하지는 못한다(등가성 검정 미수행).
  시드 20개 이상으로 확장해 신뢰구간을 좁히는 것이 후속 과제다.
- **예측 신호의 한계 기여** — 동일 제어기에서 예측 소스만 바꾼 ablation(`results/prediction_contribution.csv`,
  `python DL_LSTM/_ablation_run.py`)에서는 예측 정확도가 순절감에 단조 기여하지 않았다. 예측 기반 시스템의 우위는
  상당 부분 **제어 정책 설계** 에서 나오며, 예측 신호의 기여를 키우는 제어기–예측 통합 설계가 후속 과제다.
- **배터리 열화 비용(DoD 기반 LCOS)** 정량화로 장기 경제성 비교를 강화할 수 있다.
- **태양광 모델** — 일사량 선형 모델을 성능비·온도 보정을 반영한 물리 모델로 확장할 수 있다.
